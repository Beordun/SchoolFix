--- 3. ARCHITECTURAL ANALYSIS OF THE FAILURE ---
- Root Cause: In relational database management systems (RDBMS) like PostgreSQL, altering an existing table to add a NOT NULL column requires every existing row to immediately possess a valid non-null value for that column.
- The Trap: If an ORM simply issues `ALTER TABLE "User" ADD COLUMN "nin" TEXT NOT NULL;`, PostgreSQL aborts the transaction with code 23502 (not_null_violation) because existing rows contain NULL.
- Prisma Guardrail: Prisma catches this invariant violation at the CLI layer before touching the production database, preventing downtime and aborted transactions.
- The Resolution: You cannot add a required column to a populated table in a single atomic step. It must be executed using the Three-Step Migration Pattern (Expand -> Migrate/Backfill -> Contract).
